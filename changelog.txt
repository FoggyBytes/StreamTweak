Version 8.2.0 - "The Quiet Update" (28/08/2026)
-----------------------------------------------

⚡ IDLE CPU:
• StreamTweak used a steady slice of a CPU core while doing nothing at all — sitting in the tray, no client connected, no session running. With nothing to report it now measures nothing (reported in issue #7)
• The host metrics behind the client's overlay were most of that cost: they were read by asking one performance counter per process per GPU engine, one at a time, which re-read the whole set hundreds of times a second. One pass now gets the same numbers for a fraction of the cost, and that cost no longer grows with how busy the machine is
• Those metrics are collected only while something is actually asking for them — a connected client, or the Dashboard open in front of you
• The Dashboard's live tiles stop refreshing when the window is closed to the tray, and never start when StreamTweak launches minimised with Windows
• The watch for a new streaming-server log no longer rescans the log folder ten times a second — it looks only when the folder has actually changed, and notices a new log just as quickly as before

🟩 NVIDIA SENTINEL:
• Auto-restore now tells you in the app when it cannot put your profile back, instead of failing silently — the Dashboard badge reads "Stuck" and the Tuning page says what happened. A profile saved on a different driver version is the usual cause, and saving it again is the usual fix
• A restore that keeps failing now backs off instead of retrying every few seconds indefinitely — it could fail well over a thousand times in a day without anything in the app ever saying so
• A failed restore is no longer recorded as though it had worked, so "Last auto-restore" means what it says
• The safety-net poll runs every 30 seconds instead of every 5 — it was costing 2.5% of a CPU core around the clock, while the watch on the driver's settings database is what actually catches a reset, in milliseconds

⚠️ COMPATIBILITY:
• Host metrics take about a second to appear once a client starts asking, rather than being there instantly — they are rates, and a rate means nothing until it has been measured twice

Version 8.1.2 - "The Tray Update" (20/08/2026)
----------------------------------------------

🧰 SYSTEM TRAY:
• The tray menu is down to Open and Exit — everything else it held either repeated what the tooltip and the icon already say, or was a second copy of a control that has a proper home on one of the app's own pages
• Fixed "Restore link speed", which managed to disagree with itself three ways — with no session running it relabelled itself "Switch link speed now", a command that stopped existing in 8.1.0, while clicking it ran a restore regardless of the label, and that restore did nothing at all unless the adapter had actually been switched. The Network page has always done this properly: the button greys out and says why
• The tooltip now names the session state alongside the adapter speed, so the two status rows that used to sit in the menu are still there — hover instead of right-click
• Removed the HDR toggle — it was read once when the app started and never refreshed afterwards, so it drifted out of step with the truth: HDR gets changed from the Display & audio page, with Win+Alt+B, and by the streaming server itself on every session
• Removed the Auto Spatial Audio toggle — the Display & audio page owns that setting and keeps it correct


🔀 LINK SPEED:
• Starting another game within half a minute of the last one now gets the link matched — a session stays open for a grace period after the client disconnects, so that reconnecting rejoins the same entry in the history, and for that whole window the host was turning down every request to change the adapter. It was the one window in which starting another game is most likely, and the client had no way to know: it announced the change and then nothing happened
• A session now counts as running only while a stream really is, instead of for the grace period as well, so StreamLight can tell in advance whether a change is worth announcing and stays quiet when it is not
• The prompt that offers to put the link back when you return to the host list now appears — the same window was swallowing it, and returning to the host list is almost always inside it
🧹 UNDER THE HOOD:
• The tray menu is a plain Windows menu again instead of a hidden window drawing WinUI controls, which takes with it a first-open sizing bug that could leave the menu with a scrollbar at 125% scaling and above, along with the workarounds carried for it

Version 8.1.1 - "The Cover Art Update" (12/08/2026)
---------------------------------------------------

🖼️ COVER ART:
• Game covers no longer stop at whatever a launcher happens to keep on disk — a cover has to be full size before the search ends, so it carries on to the store's own artwork instead of settling for the small thumbnail a launcher holds for its own grid
• GOG games now get a Steam Store lookup when their local artwork is too small, which every other store already had — it was the one store without that rescue, and its covers were the smallest in the library because of it: Cyberpunk 2077 came out of GOG Galaxy at 342x482 while the same cover sits on Steam at 600x900
• Fixed the Steam address used when the store API has no cover to offer — the file named for 600x900 is in fact 300x450, so a game that fell through to it was quietly getting a quarter of the pixels
• A cover already downloaded is never replaced by a smaller one: the sources are tried fastest-first rather than best-first, so which of two you ended up with came down to which finished first

⚠️ COMPATIBILITY:
• Covers already in the cache are not re-downloaded on their own — use "Clear Sync" on the Game Library page to fetch them again at the new sizes

Version 8.1.0 - "The Handshake Update" (08/08/2026)
---------------------------------------------------

🎬 LAUNCH WATCH:
• StreamTweak now watches what happens after the streaming server is told to open a game, and tells the client when the game is really on screen. The client uses it to hold its launch screen up instead of handing you a desktop that is still rearranging itself — windows moving, a launcher opening, the resolution changing — for the several seconds before anything of the game exists. Nothing is asked for unless the client wants it: in StreamLight this is the "Wait for the game to appear" switch, off by default
• A game asked for through a store still gets watched: Steam and Xbox launches are recognised from the streaming server's own log even though they carry no command of their own, and a game reached through a launcher protocol is matched back to its install directory
• When something on the host is waiting for a click — a store client asking for a login, a game's own launcher wanting to update — that is reported too, and the client stops covering it up. A window that was already open before the launch is never mistaken for one of these: it has to be the store's own client, or a window that appeared after the launch began and then kept the screen
• The Desktop entry, and anything else that opens no window of its own, is reported as having nothing to wait for, so it is shown immediately
• A launcher that is doing its job no longer counts as one asking for a click: before saying the host needs you, StreamTweak checks whether the game's own process has started. Ubisoft Connect opens a window, starts the game and steps aside, while Battle.net opens a window and waits — watching windows cannot tell those apart, and no amount of waiting longer separates them, because one is helped by exactly as much as the other is hurt
• Battle.net titles get no launch screen at all: those launches open the client itself and the Play button you have to press is the very thing a launch screen would be covering, so there is nothing to wait for — the same answer the Desktop entry gets
• Ninety seconds is the cap: past it the host says so rather than leaving the client waiting on an answer that isn't coming

🔓 REMOTE UNLOCK:
• StreamTweak now tells an approved client whether the host is sitting at a lock or logon screen, which is what lets StreamLight offer a PIN pad after waking it instead of leaving you with a host that answers pings and does nothing else
• The brief session the client opens to type that PIN is kept out of the way entirely: it is not recorded in Sessions, it does not switch on spatial audio, it does not close and reopen your managed apps, and it credits no game. The client declares what that session is for before opening it — from the host's side one session looks like any other, and only the client knows why it opened
• The declaration is used once and expires by itself, so a client that gives up half way cannot make the next real session vanish from the history
• Nothing here types anything or unlocks anything on its own: the PIN travels on the streaming connection, the same path as the keystrokes you would send by hand, and it is the client that sends it
• Once the client is in, it closes that session properly rather than just disconnecting, so this host goes straight back to reporting itself as online — a plain disconnect is treated as a pause you might resume, which would have left it looking busy with a session nobody was watching

🖼️ HOST TILES:
• The Desktop and Steam tiles you replaced from the Library page are now put back automatically when the streaming server's own updater reinstalls its defaults over them — until now the setting stayed switched on while the tiles had quietly gone back to the server's, which is the worst of the three states it could be in
• Both a watcher and a periodic check, because an update can replace the whole assets folder rather than write into it, and a watcher on a folder that gets deleted stops watching
• Nothing is copied unless the tile on disk actually differs from ours: an installer rewrites timestamps whether or not it changed anything, and re-copying on every touch would mean writing into Program Files for nothing

🔀 LINK-SPEED SWITCH:
• The client now picks the speed and asks for it before connecting — StreamLight reads its own wired link, requests a match, and starts the stream only once the host confirms the change. Until now the switch fired when the streaming server reported a connection, which is after the session already exists: renegotiating the adapter there drops the link for several seconds and kills the very stream it was meant to help, sometimes into a connect/disconnect loop
• The host no longer configures a target speed at all — the right speed depends on the client's connection, and only the client knows what that is. The Network page becomes a status page: the adapter, its current speed, the speeds it supports, one permission switch and a manual restore
• New "Let clients change the link speed" switch — permission, not configuration. Turn it off while you need full speed for something else and clients can still read the speed but not touch it
• After the link comes back the host waits a few more seconds before telling the client it is ready — the adapter reports the new speed the moment it is up, but the streaming server's network sockets take longer than that to recover, and a stream started too early completes its handshake and then receives no video or audio at all
• The link is never renegotiated while a stream is running, even when the streaming server never reported the previous session ending — a leftover session used to leave the host believing it was idle, and the change would then break the stream actually in progress
• A restore that comes due while a stream is live is postponed instead of forced, including when StreamTweak itself is restarted mid-session
• The host no longer decides when to put the link back — it holds the streaming speed after a session ends and restores only when a client asks. StreamLight puts the question to you when you leave a host, so the speed survives the gap between two games instead of costing a renegotiation on the way out and another on the way back in
• Nothing is undone behind your back: a session ending, a game exiting on the host, a change no session ever used — none of them move the adapter on their own any more. The one thing that still acts by itself is the check at startup, which puts back a link left switched by a previous run
• Wi-Fi adapters are no longer listed — Wi-Fi has no fixed link speed to match, and the buffering this feature solves happens where a faster wired link meets a slower one. Previously a wireless adapter could be selected and would silently do nothing
• Restoring puts back the adapter's original setting, so one left on Auto Negotiation stays on it instead of being pinned to a fixed speed — while the page shows you the speed you get back, not the setting's name
• A request arriving over Tailscale, Wi-Fi or any other interface is refused: a remote client has no business renegotiating a LAN link it isn't even using

📊 SESSION REPORT:
• The last session is now shared with the client — grade, how long ago, how long it ran, round-trip time and its peak, host frame latency, frame drops and the cover art of what was played, all served to an approved StreamLight so it can show them on its own home screen. The host's Dashboard has always known this, but the host is not the machine you are sitting at when deciding whether to stream again
• Cover art travels as a thumbnail, resized on the host and cached, so a 600x900 picture is not sent for something drawn a hundred pixels wide
• The Dashboard's last-session card now shows the cover art first and the figures after it, and caps the covers at three with a "+2" for the rest — a session keeps running across one game closing and the next starting, so an afternoon with four titles used to add a fourth cover by taking the width away from the numbers beside it. Every game the session detected is still listed in Sessions

🗂️ SESSION HISTORY:
• New "Only record sessions with a game" switch in Settings — with it on, a session that never launched a game is discarded instead of being written to the history, so a connection test, a look at the desktop or a launch that went nowhere leaves nothing behind. Off by default, and it only ever applies to sessions ending from now on: nothing already recorded is touched
• It applies when a session closes, including one recovered after a crash or a host shutdown — there the played-game list comes from the checkpoint written every 30 seconds, so a game launched in the last half-minute before the interruption isn't seen and that session goes with the rest

🎨 APPEARANCE:
• New application icon, in the window, the taskbar and the installer. The two tray icons that show whether the link is on its streaming speed have been redrawn to match

🩹 FIXES:
• Closing StreamTweak during a session now records what was played — the detected games were collected on every other way a session can end but not on this one, so the session was filed as though nothing had been launched
• The Dashboard's HDR badge no longer falls back to a dash once it has read the real state. Reading the display configuration fails for stretches at a time on a host with a virtual display — the retries were also too short, and missed the error this actually returns — and HDR does not turn itself off while nobody is looking, so the last figure actually read is kept
• Epic Games titles now launch through the Epic launcher instead of by running their executable, which most of them cannot be started by at all — the entitlement and Epic Online Services tokens arrive on the command line from the launcher, so a direct launch plays the intro and drops back to the client, whether or not the launcher is already open. This applies both to streaming and to the Library page's own Play button, which are now the same decision rather than two. Re-sync the library once to rewrite the commands
• The Library page's Play button no longer starts a game in StreamTweak's own folder — it set no working directory, so the game inherited StreamTweak's and any title that looks for its data next to where it was started refused to run, reporting a missing folder under Program Files. Games launched by the streaming server were never affected
• A session that ends because the game itself exits is now recognised — until now StreamTweak only noticed a session ending when the client disconnected, so quitting a game left the session running in the history until something else ended it, a stream started shortly afterwards was merged into it, and the link speed was never put back
• The Dashboard no longer reports HDR as off when it is on — reading the display configuration can fail while Windows is rearranging monitors, which happens around every session on a host with a virtual display, and the failure was being shown as a confident "Off". It is now retried, and when the state genuinely can't be read the badge shows a neutral dash instead of claiming the feature is disabled
• Sessions are always recorded now — session history, telemetry, spatial audio and played-game detection all hang off the streaming-server log watcher, which used to be switched off together with the automatic link-speed switch
• The installer no longer opens filling the whole screen with its contents still laid out for a small window, the artwork stranded in a corner — Windows was maximising a wizard that is not meant to be resized in the first place, which showed up on handhelds

🧹 UNDER THE HOOD:
• The diagnostic log is now capped — it rolls over at 5 MB keeping a single previous copy, so it can no longer creep up to the hundreds of megabytes that long-running installs were quietly accumulating
• Routine chatter no longer reaches the log — the process scan, the bridge traffic and the streaming-server log discovery together accounted for over 99% of every line written and buried the handful of entries that actually explain a problem; all of it is still available on demand by setting "VerboseLogging" to true in config.json
• Every link-speed change is now recorded: what it was, what it became, which client asked and when it goes back. None of it was logged before, which made a misbehaving switch impossible to reconstruct afterwards
• Less work while you stream — the game detector no longer probes Windows service processes whose executable path it can never read, removing roughly seventy failed lookups every five seconds for the whole length of a session

⚠️ COMPATIBILITY:
• The automatic link-speed switch, the launch watch and the shared session report all need StreamLight 5.0.0 or later — with an older client no speed change happens at all, the host simply stays where it is, and nothing asks for the launch state or the last session
• Everything else is unchanged: pairs with StreamLight 3.3.0 for the rest of the integration, host frame-latency reporting needs StreamLight 4.0.1, and the delivered-vs-target bitrate needs StreamLight 4.5.0

Version 8.0.0 - "The UI Redesign" (18/07/2026)
----------------------------------------------

🎨 UI REDESIGN:
• The whole interface was rebuilt around what you're trying to do, not a flat list of features — the sidebar now groups everything under Dashboard, Insight (Sessions) and Host setup (Network, Display & audio, NVIDIA Sentinel, Managed apps, Library, Clients), with Settings and Glossary in the footer
• New Dashboard — one layout that never rearranges itself: only the top-left box changes with what the host is doing. At rest it's a live host monitor (GPU temperature and load, VRAM, CPU, network, refreshed every second) that finally answers "is my host cool and idle before I start?"; while you're streaming the same box becomes the live session — RTT, host latency, bitrate, frame drops and frame rate
• The rest of the Dashboard stays put in both states: your last session with its played games, a performance trend, and the full host setup alongside your paired StreamLight clients
• The Dashboard performance card summarises the period you choose — last 7, 30, 90, 180 or 365 days, or all time — and remembers your choice between launches
• The live bitrate is now shown against the target the client asked for ("of 100 Mbps target") instead of a bare number, so an undershoot is obvious at a glance — needs StreamLight 4.5.0, and falls back to the plain figure with older clients
• Every settings section was decluttered — each option is now a clean row inside a card, with the long explanations moved to a hover ⓘ that links straight to the matching Glossary entry, so the pages read as controls instead of walls of text
• Display and Audio were merged into one "Display & audio" section, bridge-client approvals moved out of Settings into their own "Clients" page, and Managed apps was reworked so its Add/Remove/End/Restart buttons live inside the list container
• The Glossary was expanded with every new 8.0 term and is reachable in one click from any ⓘ, which scrolls to and highlights the term
• Every green in the app was unified into a single palette, and every leftover Windows system-accent colour (the blue on list selection, dropdown selection, spinners, links) was replaced with green
• The interface now uses one typeface throughout — the monospaced font that used to show up in badges, values and dates was retired everywhere except the Glossary, which keeps its terminal look on purpose

🔀 LINK-SPEED SWITCH:
• "Streaming Mode" is now "Link-speed switch" and you finally choose the speed — pick the streaming target (no longer hardwired to 1 Gbps) and pick what to restore to afterwards ("Previous", or a fixed speed). The choice applies to the automatic, manual, tray and client-triggered paths alike

🎮 SESSIONS:
• A session no longer runs forever when the streaming server hangs on teardown — if the client stops sending telemetry, StreamTweak now ends the session on its own instead of leaving the counter running until you close the app
• Games launched through a store client (Ubisoft, EA, Battle.net…) are now captured reliably — StreamTweak reads the exact game the server launched from its log, so a session's played games no longer come up empty for launcher-based titles
• Sessions shorter than a minute are no longer recorded — a connection test or a stream that failed to start carries no usable telemetry and only cluttered the history

🩹 FIXES:
• Settings no longer silently revert — a corrupted config file could make every setting write fail (the spatial-audio and NVIDIA auto-restore toggles appearing to reset); the config now self-heals instead of discarding changes
• The "Excellent" quality-grade threshold for frame drops was relaxed from 0.5% to 1.0%, so a near-perfect session isn't marked down for a handful of drops
• Remote Windows Update: a Defender platform/engine update is no longer misclassified as optional, so the "Security + Defender" scope installs it instead of reporting nothing to do
• Game Library: scrolling the list no longer runs the covers flush against the Sync now / Add game buttons — the toolbar keeps a clear gap underneath it

⚙️ PLATFORM:
• StreamTweak now runs on the Windows App SDK 2.3, the current major release of the UI framework — the 1.8 line it used until now is heading out of servicing, so this keeps the app on the version that still receives fixes and performance work
• The installer handles the switch for you — the 2.3 runtime is fetched only when it's missing, and it installs alongside any older runtime already present, so upgrading from 7.x requires no uninstall and leaves other apps on your machine untouched
• The installer no longer re-downloads the Windows App SDK runtime on every single install — the check meant to detect an already-installed runtime never actually matched, so a full copy was pulled down each time even when the correct version was sitting right there
• StreamTweak now opts into the new framework's interface optimisations — lighter icons, styles applied only when they actually do something, and less work at startup
• Upgrading over an existing installation is more reliable — the background service is now stopped before files are replaced rather than after, instead of relying on Windows to notice it was in the way
• The installer is now a 64-bit build with crisper artwork, and no longer copies its own wizard images into the installation folder — about 1 MB lighter overall

🧹 UNDER THE HOOD:
• Removed the pre-8.0 leftovers now that every section lives in the new layout — the five superseded settings pages, their dead navigation entries and the view-model code only they used are gone

⚠️ COMPATIBILITY:
• Pairs with StreamLight 3.3.0 on the client; host frame-latency reporting needs StreamLight 4.0.1, and the delivered-vs-target bitrate needs StreamLight 4.5.0

Version 7.4.0 - "The Deeper Insight Update" (21/06/2026)
--------------------------------------------------------

📊 SESSION QUALITY:
• The quality grade now considers host frame latency — how long the host actually took to capture and encode each frame. This is a far more direct signal of "did the host keep up?" than encoder load %: a high latency means a late frame regardless of how busy the encoder looked. Reported by the client (StreamLight 4.x), shown in the session detail HOST panel and as a new "Host frame latency" chart. Sessions from older clients are unaffected

🛠️ HOST METRICS:
• GPU temperature and total VRAM now read through D3DKMT (the same kernel source Windows Task Manager uses), so they work on AMD and Intel GPUs too — not just NVIDIA. They also survive a graphics-driver reset (TDR) gracefully instead of risking a crash in the NVIDIA library; NVML is now only a fallback
• Network throughput is now measured on the single interface that actually carries the internet route, so Tailscale, VPN and virtual switches no longer inflate the reported TX figure

📈 CHARTS:
• RTT and Host-latency charts now draw a faint min/max band behind the average line, so a single momentary spike stays visible instead of being smoothed away when a long session is compressed to fit the chart
• New "Host compute %" chart in the session detail overlays GPU, Encoder and CPU on one shared scale with a legend, so you can read host load at a glance
• Session detail charts redesigned: they're now stacked full-width in a single scrollable column and stay readable at any window size — from the minimum window up to 4K — instead of collapsing or getting squished. Chart height grows with the window
• Session detail CLIENT/HOST panels reworked: a single consistent format across both (primary value + a dimmer max/peak/count), laid out in two compact columns so the panels are shorter; the played-game covers moved up next to the "Session Detail" title instead of a separate section at the bottom

🗂️ SESSION HISTORY:
• "Clear history" now opens a browser-style chooser — delete sessions from the last hour, 24 hours, 7 days, 4 weeks, or all time — with a red Delete confirm and a Cancel button, instead of wiping everything immediately
• New "Compare" button — pick two sessions from two dropdowns and see them side by side: every CLIENT/HOST metric with a per-value delta that highlights which session was better, every chart drawn with both sessions overlaid (each in its own colour, with a legend), and each session's detected games. The whole view stacks in a single scrollable column so it stays readable at any window size

Version 7.3.0 - "The Patch Tuesday Update" (06/06/2026)
-------------------------------------------------------

✨ NEW FEATURES:
• Remote Windows Update: an approved StreamLight client (3.3.0 or later) can now check for, and install, Windows updates on the host and restart it — all from the client, no keyboard needed on the host. Ideal for a headless gaming PC. The client shows the updates it found, classified (security & critical, Defender, optional), and you choose "Security + Defender" or "All updates". Feature/version upgrades (e.g. a new Windows version) are shown but never installed remotely — run those on the host directly
• The actual update work runs in the LocalSystem service (Windows Update Agent), so no UAC prompt; the install command is destructive (it reboots), so it requires a verified signature from an approved device, exactly like remote power-off. Download shows a real percentage; install runs to completion and the host restarts automatically only if Windows requires it
• Update and shut down: the remote power-off can now install any pending Windows updates before powering off, not just shut down. Uses Windows' documented "Update and shut down" path (InitiateShutdown), falling back to a normal power-off if updates can't be applied. The client also shows a hint when the host (or the client itself) has updates waiting for a reboot — informational only, never gates anything

🎨 UI:
• Bridge security: the StreamLight devices list now shows just the device name (e.g. "Foggy-Ally") instead of "StreamLight @ Foggy-Ally" — cleaner; existing entries are tidied up automatically
• Home dashboard: the "Managed Apps" and "Game Library" tile counts are now green, matching the Logs tile
• Status banners (info notices) across Settings, Apps and Game Library now use the same green accent as NVIDIA Sentinel for their information icon, for a consistent look

Version 7.2.0 - "The Power Update" (05/06/2026)
-----------------------------------------------

✨ NEW FEATURES:
• Remote host power-off: an approved StreamLight client (3.2.0 or later) can shut the host PC down over the authenticated bridge — straight from the host's Options menu on the client, no need to touch the host. Useful for powering the gaming PC down after a couch session ends. The shutdown command is destructive, so it is only ever accepted with a verified signature from an approved device — never unauthenticated, even in the old open mode

🙏 THANKS:
• Thanks to @SolemnDucc for suggesting this feature (https://github.com/FoggyBytes/StreamLight/issues/1)

🔒 SECURITY:
• Bridge authentication is now mandatory. The toggle that allowed turning authentication off (legacy open bridge) has been removed: only StreamLight devices you have approved can use the advanced integration. This never affects streaming itself — your games stream the same whether a device is approved or not — it only gates host metrics, NIC speed / Streaming Mode, store badges, session reports, the Tailscale dual-tile, remote pause and the new power-off. The Bridge security card now explains this in place of the old toggle

🗑️ REMOVED:
• The Store tab (embedded Instant Gaming browser) has been removed, along with the WebView2 runtime it required. The installer no longer downloads or installs WebView2

⚠️ COMPATIBILITY:
• Requires StreamLight 3.2.0 or later for the new power-off feature and for the advanced integration in general. Update both apps together

🐛 BUG FIXES:
• Session logs — games missing on host shutdown: games played during a session that ended via host PC shutdown or power loss were not recorded in the session log. • Phantom session from stale log file: CheckForExistingSession() Phase 2 (head-of-file scan) could fire a retrospective StreamStarted event from an old log entry when no session was actually in progress. Fixed by requiring a positive TCP check (HasActiveMoonlightSession) before raising the event

• Session telemetry — file concurrency: SessionLogger Load() and Save() are now guarded by a static lock, preventing sessions.json corruption if a concurrent write races (e.g. OS session-ending event vs. session stop)
• Session quality grade — RTT spike sensitivity: a session with a good average RTT but at least one spike above 200 ms now has its RTT grade downgraded by one level, reflecting the perceptible lag experienced by the user
• SparklineControl — Y-axis label mismatch: the max and midpoint labels showed the raw data range before the margin was added, while the polyline was drawn on the margin-padded range. On low-variance data (e.g. RTT 1–3 ms) both labels collapsed to the same integer (e.g. "2" top and "2" midpoint). Labels now reflect the actual visible scale
• Home panel — HDR / Auto HDR status: the HDR and Auto HDR pills were not updated in real-time. They now refresh on every Home tab click (live read from Windows), on Display tab open/refresh, and on toggle. Opening the window during an active streaming session also triggers a live read, correctly reflecting virtual display HDR state
• Internal cleanup: removed unused _fpsTimeSeries accumulator that was collecting one float per second for the entire session duration without ever being persisted or displayed

🐛 BUG FIXES — GAME LIBRARY:
• Xbox/Game Pass scanner — .GamingRoot parsing: the header offset was computed as 5 bytes (magic 4 + 1 unknown) instead of the correct 8 bytes (magic 4 + version DWORD 4), producing a corrupted relative path that never resolved to an existing directory; Xbox and Game Pass games were therefore never detected. Offset corrected to 8 — Forza Motorsport and other Xbox App titles now appear in the library after sync
• Game Library — race condition on Add / Remove: AddManualGameAsync and RemoveGameAsync accessed GameLibraryState and apps.json without holding _syncLock, allowing concurrent writes to race with an in-progress full sync and corrupt either gamelibrarystate.json or apps.json. Both methods now acquire _syncLock with a 5-second timeout before proceeding
• gamelibrarystate.json — non-atomic write: Save() wrote directly to the destination file; a crash or forced shutdown mid-write produced a truncated JSON file that was silently discarded on next startup, causing the entire game library to disappear. Save() now writes to a .tmp file first and moves it atomically over the destination
• Cover art cache — non-atomic PNG write: CoverArtFetcher wrote decoded PNG frames directly to the cache path; an interrupted write left a permanently corrupt file that the existence check considered valid, preventing the image from ever being re-fetched. Now writes to a .tmp path and moves atomically, matching the pattern already used in StoreCoverFetcher
• SunshineSync.AddApp — incomplete deduplication: the duplicate check only matched entries marked _streamtweak_managed, so adding a manual game whose name matched an existing Sunshine-native app produced a duplicate entry in apps.json. The check now matches any entry regardless of the managed flag
• GameLibraryService — inverted sync fail-safe: the ?? true fallback in the gamesToSync filter included any game that could not be matched in the merged list, which is a dead code path under normal operation but would incorrectly sync disabled games if the merge logic were ever extended. Changed to ?? false for correct fail-safe semantics

Version 4.4.0 - The "Telemetry Update" (20/03/2026)
---------------------------------------------------

✨ NEW FEATURES:
• Host metrics collection: StreamTweak now collects real-time host PC metrics — GPU usage %, GPU encoder usage %, GPU temperature (°C, NVIDIA only via NVML), VRAM used (MB), VRAM total (MB, NVIDIA only), CPU usage %, and network TX (Mbps) — and serves them to StreamLight via a new STATS command on the TCP bridge (port 47998)
• STATS command: the TCP bridge accepts a new STATS command that returns a JSON payload (e.g. {"gpu":45,"gpu_enc":12,"gpu_temp":62,"vram_used":4096,"vram_total":8192,"cpu":18,"net_tx":80}) for consumption by StreamLight's overlay
• Cross-vendor GPU metrics via PDH PerformanceCounters: GPU utilization (3D engine), GPU encoder utilization, and VRAM used are read with System.Diagnostics.PerformanceCounter using the GPU Engine and GPU Process Memory performance counters — works on NVIDIA, AMD, and Intel Arc
• NVML P/Invoke for GPU temperature and total VRAM (NVIDIA only): temperature and total VRAM capacity are read directly from nvml.dll (shipped with NVIDIA drivers) via P/Invoke; on non-NVIDIA systems these fields report -1 and no error is raised
• Metrics unavailable for StreamLight: if StreamTweak is not reachable or metrics are not available, StreamLight's overlay omits the host metrics section entirely — no fallback values, no placeholders

🔧 IMPROVEMENTS:
• HostMetricsCollector initialises asynchronously on a background Task to avoid any impact on WPF startup time
• GPU Engine PDH counter list is rebuilt every 60 seconds to handle processes appearing and disappearing at runtime (instances are per-process and ephemeral)
• VRAM reads use RawValue (int64) instead of NextValue (float) to avoid precision loss on systems with more than 2 GB of dedicated VRAM
